# DP0018: Value object property should not be a mutable collection or array

| Property | Value |
| :--- | :--- |
| **Rule ID** | DP0018 |
| **Category** | Design |
| **Default Severity** | Warning |
| **Enabled by Default** | true |

## Description

Value objects must be deeply immutable. Properties of type array (`T[]`) or mutable collections like `List<T>`, `Dictionary<TKey, TValue>`, or `HashSet<T>` allow callers or external code to mutate internal state after instance creation, violating domain invariant guarantees and structural equality semantics.

## How to Fix

Replace mutable collections or raw arrays with deeply immutable types such as `System.Collections.Immutable.ImmutableArray<T>`, `IReadOnlyList<T>`, or custom domain collection wrappers implementing read-only interfaces:

```csharp
// ❌ Violation: Array allows internal mutation
[ValueObject]
public readonly partial record struct OrderLines
{
    public required LineItem[] Items { get; init; }
}

// ✅ Fix: Use ImmutableArray<T> to guarantee deep immutability
[ValueObject]
public readonly partial record struct OrderLines
{
    public required ImmutableArray<LineItem> Items { get; init; }
}
```
