# RFC 0001: StrongId Factory Naming Standardization

## Context
In the `StrongId<T>` generator, the factory method to create a new, unique identifier (e.g., for `Guid`-backed IDs) was originally named `New()`, while the method to create an identifier from an existing value was named `From()`.

However, across the rest of the `EricksonLopez.DomainPrimitives` ecosystem (string primitives, numeric primitives, value objects), the standardized factory methods are `Create()` (throws on invalid) and `TryCreate()` (returns a `Result<T>`).

This inconsistency violates the BCL naming consistency principle (Framework Design Guidelines) and increases the cognitive load for developers, who must remember that `StrongId<T>` uses different factory names than `[StringPrimitive]`.

## Proposed Change
We propose renaming the `StrongId<T>` factory methods as follows:
- `New()` -> `Create()`
- `From(value)` -> `Create(value)`

This aligns `StrongId<T>` with all other primitives generated by this library.

## Breaking Change
This is a **binary and source breaking change**. Any existing code calling `YourId.New()` or `YourId.From(value)` will fail to compile. 

## Migration Path
1. Replace all calls to `YourId.New()` with `YourId.Create()`.
2. Replace all calls to `YourId.From(value)` with `YourId.Create(value)`.
3. If using reflection to find the factory method, update the method name string.

## Alternatives Considered
- **Keep `New()` and `From()`**: Rejected because it maintains inconsistency across the library.
- **Add `Create()` but keep `New()` as `[Obsolete]`**: Rejected because this is a pre-GA (v1.1.2) breaking change, and keeping deprecated members before v1.0 adds unnecessary API surface area.

## Approval
This RFC is approved by the API Review committee to standardize the API surface prior to v1.0 GA.
