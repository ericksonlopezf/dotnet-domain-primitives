# Security Policy

## Supported Versions

| Version | Supported | Notes |
| ------- | --------- | ----- |
| 1.1.x   | :white_check_mark: | Current release |
| 1.0.x   | :white_check_mark: | Security patches only |
| < 1.0   | :x: | Pre-release; not supported |

> Only the latest minor version receives active maintenance. The previous minor version (`1.0.x`) receives critical security patches only. Users are encouraged to stay on the latest release.

## Reporting a Vulnerability

If you discover a security vulnerability within `DomainPrimitives`, please send an e-mail to [ericksonlopezf@gmail.com](mailto:ericksonlopezf@gmail.com). All security vulnerabilities will be promptly addressed.

**Do not** open a public GitHub issue for security vulnerabilities. Use [GitHub Private Security Advisories](https://docs.github.com/en/code-security/security-advisories) or the email above.

## Supply Chain Security

To ensure the integrity of the packages distributed via NuGet, this project implements the following supply chain security measures in its automated CI/CD pipelines:

1. **NuGet Trusted Publishing:** We use OpenID Connect (OIDC) to authenticate with NuGet.org, eliminating the need for long-lived static API keys.
2. **Sigstore Provenance Attestation:** All packages are signed using `sigstore-cli` during the CI workflow to provide verifiable cryptographic attestation of their origin.
3. **Strong Name Signing:** All assemblies are signed with a strong name key (`EricksonLopez.snk`) to guarantee assembly identity and integrity.
4. **Deterministic Builds:** Enabled via `<Deterministic>true</Deterministic>` in `Directory.Build.props`, ensuring identical source produces bit-for-bit identical assemblies.
5. **Source Link:** `Microsoft.SourceLink.GitHub` embeds source control metadata, allowing consumers to step into library source code during debugging.
6. **NuGet Audit:** `<NuGetAudit>true</NuGetAudit>` with `<NuGetAuditLevel>low</NuGetAuditLevel>` scans all dependencies for known vulnerabilities at restore time.

## Known Security Boundaries

DomainPrimitives enforces six security gates automatically on all string-backed primitives. For full documentation, see [docs/security.md](docs/security.md).

| Gate | Protection | Default |
|:-----|:-----------|:--------|
| SEC-001 | 4096-character hard limit on all strings without explicit `MaxLength` | Always on |
| SEC-002 | `RegexOptions.NonBacktracking` on .NET 7+ (eliminates ReDoS) | Always on (.NET 7+) |
| SEC-003 | 100ms regex timeout on older TFMs | Always on (pre-.NET 7) |
| SEC-004 | NFC Unicode normalization before validation | Always on |
| SEC-005 | No PII echoed in error messages | Always on |
| SEC-006 | `stackalloc` ≤ 256 chars; `ArrayPool<char>` for larger inputs | Always on |

### Regular Expression Denial of Service (ReDoS)

On .NET 7+, all regex-based validation generated by `StringPrimitiveGenerator` uses `RegexOptions.NonBacktracking`, which evaluates in guaranteed O(n) time, eliminating the entire class of ReDoS vulnerabilities.

On earlier TFMs where `NonBacktracking` is unavailable, a hard **100ms timeout** (`TimeSpan.FromMilliseconds(100)`) is enforced as a fallback defense.

If you provide a custom `Regex` pattern to `[StringPrimitive]`, it inherits these protections automatically.
